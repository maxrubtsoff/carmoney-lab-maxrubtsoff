# Код-ревью перед мержем

## Порядок работы
1. Посмотреть изменения, готовящиеся к мержу (`git diff main...HEAD`).
2. Проверить логику и корректность.
3. Отметить грубые ошибки — поломку логики или данных.
4. Записать замечания в файл по шаблону [template.md](template.md).

## Формат результата
- Результат всегда кладётся в файл `docs/review/review_<ID задачи>.md`, даже если просьба короткая
  или неформальная («можно мержить?»). ID задачи берётся из просьбы или из имени ветки (`d2/2.2.1-2.2.3-…` → `2.2.1-2.2.3`).
- В чат уходит короткое резюме: сколько грубых ошибок и сколько замечаний, путь к файлу.
- Каждое замечание: `файл:строка` + суть.
- Код не править и рефакторинг не предлагать: ревью только описывает проблемы.

## Чек-лист
- [ ] Логика и корректность проверены
- [ ] Грубые ошибки (поломка логики или данных) отмечены
- [ ] Пороги и константы берутся из `backend/config/rules.php`, литералов этих чисел в коде нет
- [ ] Рефакторинг не предлагается
- [ ] Результат записан в `docs/review/`, а не только в чат
