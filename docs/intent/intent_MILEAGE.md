# Intent MILEAGE — правило «пробег не больше 400 000 км, иначе review»

## 1. Замысел

В расчёт решения по заявке добавляется правило: если пробег авто строго больше
400 000 км, итоговое решение — review, каким бы ни было решение по LTV (approve
или reject). Правило уровня решения, а не валидации: заявки с отсутствующим или
невалидным пробегом продолжают получать 422, а не review.

## 2. Зачем

Сегодня решение считается только по LTV, пробег на него не влияет:
авто с пробегом 450 000 км при LTV 50% получает автоматический approve.
Высокий пробег — сигнал риска по залогу (износ), такие заявки должны уходить
на ручной просмотр вместо автоматического решения. — «постановка задачи (интервью)»,
«код: backend/src/Domain/DecisionEngine.php»

## 3. Constraints

- Порог 400 000 км, срабатывает строго больше: 400 000 — ещё approve,
  400 001 — review. — «ответ в интервью» (вопрос 1)
- Отсутствующий/невалидный пробег — без изменений: 422 «Пробег от 0 до 500000 км»,
  валидацию не трогаем. — «ответ в интервью» (вопрос 2),
  «код: backend/src/Domain/ApplicationValidator.php»
- Правило перекрывает любое решение по LTV, включая reject → review —
  сознательное смягчение, подтверждено человеком. — «ответ в интервью» (вопрос 3)
- Порог хранится в конфиге бизнес-правил, секция vehicle, ключ
  mileage_review_above_km = 400000; валидационный потолок max_mileage_km = 500000 —
  другое число, остаётся как есть. — «ответ в интервью» (вопрос 4),
  «код: backend/config/rules.php»
- Окно действия на валидном пробеге: 400 001…500 000 (выше 500 000 — 422
  до расчёта решения). — «код: ApplicationValidator.php, rules.php»
- Ветки решения по LTV не меняются: approve / review / reject по текущим порогам. —
  «код: backend/config/rules.php»
- approved_limit при review по пробегу — 0, как у любого не-approve. —
  «код: backend/src/Domain/AssessmentService.php»
- Правило действует везде, где считается решение: при сохранении заявки и в
  предварительном расчёте LTV. — «код: backend/src/Http/ApplicationController.php»
- Порог и семантика — решение риск-менеджмента; ожидания тестов под зелёный
  прогон не подгоняются (AGENTS.md п.5). — «ответ в интервью»

3. Перекрывает ли правило reject — закрыт (интервью: любое решение → review).
4. Размещение порога в конфиге — закрыт (интервью: vehicle.mileage_review_above_km).
5. Границы задачи — закрыт (интервью: см. раздел 5).
6. Пересчитывать ли решения уже сохранённых заявок (в т.ч. seed) или правило

   видно, что решение фиксируется при сохранении заявки).
