# E2E проверка формы: пробег 400001 и пробег 600000

Дата прогона: 2026-10-08, через Playwright, против `http://localhost:8080` (HTTP 200 на `/health` до прогона).

Окружение в момент прогона:
- Сервис: `carmoney-lab`, заголовок страницы «Предварительная оценка заявки — carmoney-lab».
- URL после действий: `http://localhost:8080/`.
- В консоли браузера до первого сабмита — 1 ошибка; после второго сабмита — 2 ошибки (тексты ошибок консоли в этот отчёт не сняты).

## Что в форме по умолчанию

В форме при первом открытии страницы (значения `value` инпутов):

| Поле | id | name | value |
|---|---|---|---|
| Идентификатор клиента | `applicant_ref` | `applicant_ref` | `CL-0025` |
| VIN | `vin` | `vin` | `XTA21099998765432` |
| Год выпуска | `year` | `year` | `2019` |
| Пробег, км | `mileage` | `mileage` | `84000` |

Кнопки: «Отправить заявку», «Только рассчитать LTV».

## Случай 1 — пробег 400001, остальные поля по умолчанию

Шаги:
1. Открыл `http://localhost:8080` через Playwright (`page.goto`). Заголовок: «Предварительная оценка заявки на заём под ПТС».
2. Программно очистил поле `mileage` (`el.value = ''`) и перевёл фокус.
3. Ввёл в поле «Пробег, км» значение `400001` через `browser_type`. Перед сабмитом контрольная проверка значений формы:
   - `applicant_ref = "CL-0025"`
   - `vin = "XTA21099998765432"`
   - `year = "2019"`
   - `mileage = "400001"`
   - `market_value = "900000"`
   - `requested_amount = "450000"`
   - `term_months = "24"`
4. Нажал кнопку «Отправить заявку» (`browser_click`).
5. Подождал 1 секунду.
6. Снял скриншот всей страницы: `docs/setup/e2e_case1_mileage_400001.png`.

Что показала система (дословно со страницы, секция «Решение»):
- Заголовок секции: «Решение»
- «Решение»: `review`
- «LTV»: `50 %`
- «Возраст авто»: `7 лет`
- «Одобренный лимит»: `0 ₽`
- «Номер заявки»: `30`

Скриншот: `docs/setup/e2e_case1_mileage_400001.png`.

## Случай 2 — пробег 600000, остальные поля по умолчанию

Шаги:
1. На той же открытой странице (после случая 1) программно очистил поле `mileage` (`el.value = ''`) и перевёл фокус.
2. Ввёл в поле «Пробег, км» значение `600000` через `browser_type`. Контрольная проверка: `document.getElementById('mileage').value === "600000"`.
3. Нажал кнопку «Отправить заявку» (`browser_click`).
4. Подождал 1 секунду.
5. Снял скриншот всей страницы: `docs/setup/e2e_case2_mileage_600000.png`.

Что показала система (дословно со страницы, секция ошибок):
- Заголовок секции: «Заявка не принята»
- Список ошибок, единственный пункт: `mileage: Пробег от 0 до 500000 км`

Секции «Решение» на странице нет — она не появилась.

Скриншот: `docs/setup/e2e_case2_mileage_600000.png`.

## Что не выдумывалось

- Текст решения/ошибки скопирован из DOM-снимка после клика, не из памяти о правилах.
- Сообщение «Пробег от 0 до 500000 км» взято со страницы, а не из `ApplicationValidator::validate()`.
- Номер заявки `30` взят со страницы случая 1; счётчик заявок в БД не проверялся отдельно.
- Текст ошибок консоли браузера не извлекался — в отчёте только то, что отрендерилось в форме.

## Проверка отчёта человеком (после прогона агента)

Оба скриншота открыты и сверены с текстом выше: значения в формах (400001 и 600000, остальные поля
по умолчанию), блок «Решение» и блок «Заявка не принята» совпадают с описанием, расхождений нет.

Одно визуальное отличие, которое не расхождение с кодом: на скриншоте решение написано заглавными,
`REVIEW`, а в тексте отчёта — `review`. В DOM лежит `review` (`frontend/app.js`, `data.decision`), заглавными
его делает CSS (`.decision { text-transform: uppercase; }` в `frontend/styles.css`).

Ошибки консоли браузера (в отчёте их тексты не снимались; прочитаны из лога Playwright):
1. `404` на `/favicon.ico` — у сервиса нет иконки, на проверку не влияет;
2. `422` на `POST /api/applications` — это и есть ожидаемый отказ валидатора при пробеге 600000
   (`vehicle.max_mileage_km = 500000`).

Соответствие коду: 400001 → `review`, лимит 0 (`DecisionEngine::decide()` + `approved_limit` в
`AssessmentService::assess()`); 600000 → 422 с ошибкой `mileage` до расчёта решения
(`ApplicationValidator::validate()`).

★ (второе место в интерфейсе, где правило видно пользователю) в этом прогоне не проверялось.
По коду (`frontend/app.js`) это кнопка «Только рассчитать LTV»: она шлёт `POST /api/ltv` и показывает
тот же блок «Решение», но с номером заявки «не сохранена». В браузере не проверено.

Дополнение (2.1.4): ★ проверен в браузере в сессии 2.1.4. Агент нажал «Только рассчитать LTV» для пробега 400001
(год 2019, оценка 900000, сумма 450000, срок 24): решение REVIEW, LTV 50 %, 7 лет, лимит 0 ₽, номер заявки
«не сохранена». Скриншот: `docs/setup/pipeline_session1_review.png`.
