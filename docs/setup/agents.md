# Свои агенты: planner и scout

## planner (`.kilo/agents/planner.md`)

- `mode: primary`; `edit`: всё запрещено, кроме `docs/plan/**`; `bash: deny`.
- Что можно: читать код, `AGENTS.md`, `docs/setup/code_map.md`; писать план в
  `docs/plan/` с разделами Файлы/Шаги/Тесты/Риски (граничные значения — отдельной
  строкой в разделе Тесты). Код не меняет никогда — проверено на запросе
  «добавь комментарий в backend/public/index.php»: вместо правки записал план
  `docs/plan/plan_INDEX-COMMENT.md`.
- Может вызывать субагента `scout` — сам решает, когда это нужно: на запрос
  «найди все места, где читается пробег» без явного `@scout` planner сам
  выбрал разведчика («Это задача для разведчика») и одобрил вызов автоматически.

## scout (`.kilo/agents/scout.md`)

- `mode: subagent`; `edit: deny`, `bash: deny` — только чтение, ничего не может
  изменить и не должен предлагать исправления.
- Что можно: искать по коду и возвращать список: файл, строка, одна фраза.
- Что вернул на «найди все места, где читается пробег (mileage)»: список по
  категориям (production-код, frontend, конфиг, БД, тесты, документы) — сверено
  построчно с реальными файлами (`ApplicationValidator.php`, `ApplicationRepository.php`,
  `rules.php`, `schema.sql`, `seed.sql`, `frontend/*`, тесты) — расхождений нет.

**Замечание:** в ответе scout, помимо списка мест, есть блок «Итог» с выводом о
точке вставки будущей фичи — это уже рекомендация/анализ, а не просто список,
что выходит за рамки его собственной инструкции («ничего не меняешь и не
предлагаешь исправлений»). Права (`edit: deny`, `bash: deny`) это не нарушает —
scout ничего не менял, но по роли ему стоило бы отдать чистый список и
остановиться на нём, оставив синтез planner'у.
