# Проверка скилла code-review (2.2.2)

Одна и та же просьба без слова «скилл», в двух отдельных новых сессиях `code` (MiniMax M3):

> Посмотри backend/src/Repository/ApplicationRepository.php перед мержем.

Прогон 1 — со скиллом `.kilo/skills/code-review/` (после `/reload`), прогон 2 — папка скилла убрана из `.kilo/skills/`,
после `/reload` в Settings → Skills его нет. Файл ревью из прогона 1 перед прогоном 2 тоже убран из `docs/review/`.

## Два ответа рядом

| | Со скиллом (прогон 1) | Без скилла (прогон 2) |
|---|---|---|
| Взял ли скилл | Да: в ленте «Навык · code-review», первым шагом после рассуждения («There's a code-review skill available») | Нет: сразу «Чтение · ApplicationRepository.php» |
| Что делал | `git diff main...HEAD` по файлу (пустой, файл с `main` не менялся), `git status`, `git log`; по записи в файле ревью, для контекста смотрел контроллер, `db/schema.sql`, `backend/config/rules.php` | Прочитал только `ApplicationRepository.php` |
| Где результат | Файл `docs/review/review_2.2.2.md` по `template.md`: грубые ошибки, замечания, «Не проверялось», вывод | Только текст в чате |
| Находки | SQL-инъекция через `$status` (`:92`), `save()` без транзакции (`:22-61`), N+1 (`:99-110`), мелкое замечание про приведение `$id` | SQL-инъекция (`:92`, `:95`), N+1 (`:101-107`) |
| Транзакция в `save()` | Найдена | Не найдена |
| Раздел «что не проверялось» | Есть (тесты не запускались и не читались, нюансы дедупликации и гонок) | Нет |
| Вердикт | «нельзя мержить» с причиной | «блокер для мержа» |
| Код | Не правил | Не правил, но спросил: «Хотите, чтобы я починил, или правите сами?» |

Сверка с кодом (`ApplicationRepository.php`, `ApplicationController.php`): все ссылки `файл:строка` в обоих ответах реальны.
Общая неточность: оба ответа назвали `$limit` небезопасным, хотя в сигнатуре у него тип `int` и инъекции через него нет
(прогон 2 при этом советует «привести к int»). Прогон 1 ещё написал, что `find()` «приводит `$id` к `int`»:
в `find()` это объявление типа, приведение делает контроллер.

## Что изменилось со скиллом

Агент взял скилл сам, без слова «скилл» в просьбе, и выдал ревью в моём формате: файл `docs/review/review_<ID>.md`
с шаблоном, разделом «Не проверялось» и вердиктом, нашёл ещё одну грубую ошибку (нет транзакции в `save()`) и не предложил чинить код;
без скилла получился короткий ответ в чате без шаблона и с предложением править самому.

## Оговорки

- Один прогон на каждую ветку: разницу в находках (транзакция) нельзя уверенно приписать скиллу. Прогон со скиллом, кроме того, читал больше файлов.
- Скилл с первого раза взят, поэтому `description` не правился, версий «до и после» нет (★ не понадобился).
- Финальный чат-ответ прогона 1 и счётчики токенов обоих прогонов в этой проверке не снимались.
- В `docs/review/README.md` проекта свои соглашения (`selfreview_<ID>.md`, градации blocker / major / minor, ссылка на REQ/AC);
  формат скилла `code-review` проще и с ними пока не сведён.
