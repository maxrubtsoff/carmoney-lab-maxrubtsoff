Трек «Разработчик». Команда: [`.kilo/commands/review-diff.md`](../../.kilo/commands/review-diff.md).
Шаги ревью, формат и чек-лист живут в скилле [`code-review`](../../.kilo/skills/code-review/SKILL.md) (2.2.1):
команда на него ссылается и добавляет только то, чего в скилле нет (что именно ревьюить, ID задачи, куда положить файл, чего не делать).

## 2.4.1 — команда из рутины, один вызов


## 2.4.2 — параметр: файл или ветка

В команду добавлен параметр `$ARGUMENTS` — путь к файлу или имя ветки. В теле описано:
файл → `git diff main...HEAD -- <путь>` (пусто — ревью по содержимому); ветка → `git diff main...<имя>`;
нет ни того, ни другого — ничего не ревьюить и переспросить; пусто — спросить одной строкой и ждать (★).
Имя файла результата получило суффикс цели: `docs/review/review_<ID>_<имя>.md`, иначе два вызова на одной ветке перезаписали бы друг друга.

Каждый вызов — в новой сессии `code`.

| Вызов | Результат | Что нашёл |
|---|---|---|
| `/review-diff backend/src/Repository/ApplicationRepository.php` | [`review_2.4.1-2.4.3_ApplicationRepository.md`](../review/review_2.4.1-2.4.3_ApplicationRepository.md) | 2 грубые: SQL-инъекция `:92`, `save()` без транзакции `:24-58`; 3 замечания: литерал `50` `:87`, `$limit` без bind `:95`, N+1 `:100-107`. Вывод: нельзя мержить |
| `/review-diff backend/src/Domain/DecisionEngine.php` | [`review_2.4.1-2.4.3_DecisionEngine.md`](../review/review_2.4.1-2.4.3_DecisionEngine.md) | 1 грубая: граница approve — в коде `$ltv < approve_max` (`DecisionEngine.php:40`), а в докблоке класса и в `rules.php` `LTV <= approve_max`; при LTV ровно 60.0 решение `review` вместо `approve`, тестом граница не покрыта. 2 замечания. Вывод: нельзя мержить, пока граница не подтверждена |
| ★ `/review-diff` (без параметра) | файл не создан | В чат одна строка: «Что ревьюить: путь к файлу или имя ветки?». Git и файлы кода не трогал, цель не выбирал |

Параметр реально влияет на результат: разные цели — разные файлы ревью, разные находки и разный контекст
(для репозитория агент читал контроллер, для движка решений — `rules.php`, `LtvCalculator`, тесты).
Находку про границу `<` / `<=` я сверил руками: `DecisionEngine.php:40` против `DecisionEngine.php:10` и `rules.php:42` — расхождение реальное.

## 2.4.3 — чужой вход

Чужой вход: ветка `hw1/dz1-maxrubtsoff` (домашка 1, фича MILEAGE). Команда её не видела: до этого ей давали только файлы,
и ветка уже влита в `main` через PR #6.

| Чужой вход | Что сломалось | Что поправил |
|---|---|---|
| `/review-diff hw1/dz1-maxrubtsoff` | 1) Предположение о структуре: «ветка = есть diff с `main`». `git diff main...hw1/dz1-maxrubtsoff` пустой (ветка влита), правила на этот случай в команде не было — агент создал пустое ревью «0 ошибок, 0 замечаний, мержить нечего», фичу не посмотрел. 2) Имя файла: `<имя>` = имя ветки со `/` → вложенная папка `docs/review/review_…_hw1/`; агент сам заменил `/` на `-`, но это импровизация, а не команда | П.3: для пустого diff влитой ветки ревьюить то, что она принесла — `git diff M^1...<ветка>`, где `M` — первый merge-коммит из `git log main --merges --ancestry-path <ветка>..main`; нет merge-коммита — файл не создавать и спросить. П.6: в `<имя>` `/` → `-`, явно сказано, зачем суффикс к имени из скилла |

Повтор на том же входе после правки, новая сессия: агент нашёл merge `b95991f` (PR #6), сделал ревью по `git diff c29d3cf...hw1/dz1-maxrubtsoff`
(12 файлов, +528/−68), сверил логику со спекой MILEAGE. Результат: [`review_2.4.1-2.4.3_hw1-dz1-maxrubtsoff.md`](../review/review_2.4.1-2.4.3_hw1-dz1-maxrubtsoff.md),
0 грубых ошибок, 4 замечания (главное — то же расхождение докблока `DecisionEngine` `<=` с кодом `<`, что и в 2.4.2). Имя файла — без вложенной папки.

Осталось сознательно: ID задачи в имени файла берётся из текущей ветки (`2.4.1-2.4.3`), а не из ревьюируемой — ревью кладётся в задачу,
в рамках которой его делали. Агент отметил это как неоднозначность, но поведение совпадает с текстом команды.
